### 3.2 关键 R 代码：构建分析数据

以下是本阶段最核心的代码结构。

```
library(tidyverse)

# 读取数据：保留原始编码
person <- read_csv(
  "data/raw/perv2pub.csv",
  col_types = cols(.default = col_character())
)

trip <- read_csv(
  "data/raw/tripv2pub.csv",
  col_types = cols(.default = col_character())
)

# 个人唯一性检查
stopifnot(
  anyDuplicated(
    person[c("HOUSEID", "PERSONID")]
  ) == 0
)

# 汇总每个人的行程
trip_summary <- trip %>%
  mutate(
    miles = parse_double(TRPMILES)
  ) %>%
  group_by(HOUSEID, PERSONID) %>%
  summarise(
    n_trips = n(),

    all_valid = all(
      is.finite(miles) & miles >= 0
    ),

    mean_trip_miles = if (all_valid) {
      mean(miles)
    } else {
      NA_real_
    },

    .groups = "drop"
  )

# 与个人表连接
person_day <- person %>%
  left_join(
    trip_summary,
    by = c("HOUSEID", "PERSONID"),
    relationship = "one-to-one"
  ) %>%
  mutate(
    age = parse_double(R_AGE),
    hh_size = parse_double(HHSIZE),
    vehicles = parse_double(HHVEHCNT),
    person_weight = parse_double(WTPERFIN),
    recorded_trips = coalesce(n_trips, 0L)
  )

# 分阶段筛选
adult <- person_day %>%
  filter(age >= 18)

traveller <- adult %>%
  filter(recorded_trips > 0)

valid_distance <- traveller %>%
  filter(all_valid)

valid_density <- valid_distance %>%
  filter(HTPPOPDN %in% sprintf("%02d", 1:8))

analysis_data <- valid_density %>%
  filter(
    WORKER %in% c("01", "02"),
    hh_size > 0,
    vehicles >= 0,
    TRAVDAY %in% sprintf("%02d", 1:7),
    is.finite(person_weight),
    person_weight > 0
  ) %>%
  mutate(
    density_band = factor(
      HTPPOPDN,
      levels = sprintf("%02d", 1:8)
    ),
    worker = factor(WORKER),
    car_group = factor(
      case_when(
        vehicles == 0 ~ "0",
        vehicles == 1 ~ "1",
        TRUE ~ "2+"
      ),
      levels = c("0", "1", "2+")
    ),
    day_of_week = factor(TRAVDAY),
    log_mean_trip = log1p(mean_trip_miles)
  )
```

这段代码的重点不是复杂语法，而是它确保每个分析对象只有一个结果值，不重复计算多人或多次行程。

还有两个必须保留的细节。

第一，9,052 名候选成年出行者中，有 49 人的平均已记录行程距离为 0。他们有出行记录，所以不等同于当天没有出行的人，不能直接删除。

第二，31 号文件中基础控制变量的完整性检查没有进一步减少样本，但如果你后来增加收入、地区或其他字段，最终完整案例数可能会改变。必须重新检查，而不能强制维持 9,052。

### 5.2 正式模型结构

M0

人口与家庭基本控制模型

\\[ Y_i=\beta_0+\beta_1Age_i+\beta_2Age_i^2+ \beta_3Worker_i+\beta_4HHSize_i+ \boldsymbol\gamma^\top Day_i+\varepsilon_i \\]

M1

加入人口密度

\\[ M1=M0+\text{Density categories} \\]

M2

加入家庭车辆数

\\[ M2=M1+\text{Car ownership} \\]

M3

可选异质性交互模型

\\[ M3=M2+\text{Density}\times\text{Car ownership} \\]

由于人口密度为八个类别，模型会估计不同类别相对于参考类别的系数，而不是单一的“密度每增加一单位”的斜率。

### 5.3 R 回归代码骨架

```
# 先确定同一回归样本
model_data <- analysis_data %>%
  select(
    log_mean_trip,
    age, worker, hh_size,
    day_of_week,
    density_band, car_group
  ) %>%
  drop_na()

# M0：基本控制
m0 <- lm(
  log_mean_trip ~
    age + I(age^2) +
    worker + hh_size + day_of_week,
  data = model_data
)

# M1：加入人口密度
m1 <- update(
  m0,
  . ~ . + density_band
)

# M2：加入家庭车辆数
m2 <- update(
  m1,
  . ~ . + car_group
)

# 检验密度是否增加解释作用
anova(m0, m1)

# 比较汽车拥有量加入前后
anova(m1, m2)

# 查看模型
summary(m0)
summary(m1)
summary(m2)
```

上面的 R 代码为三个确定的主要模型。M3 不建议直接机械加入，因为 31 号文件已经发现某些密度组与零汽车家庭的交叉样本非常少。

如果最终决定合并人口密度为四组开展交互分析，应先建立同样使用四组密度的基础模型，再添加交互，比较两个真正嵌套且使用相同样本的模型。

需要重点解读的结果： 不是仅仅判断各密度组的 P 值是否显著，而是观察组间差异有多大、95% 置信区间是否较宽、加入控制变量后是否发生实质变化，以及总体密度变量的联合检验结果。

对于含多类别因子的回归，`vif()` 可能返回 GVIF，需要按照相应自由度的调整后指标解读，不能直接把所有原始 GVIF 与普通单变量 VIF 作相同判断。

这部分的实际价值不只是得到检验数字，而是回答：

模型在哪些方面存在风险？这些风险可能使人口密度系数发生怎样的偏误？下一步应该如何修正？

另外，人口密度与出行距离是观察性数据中的条件关联。居住自选择、未观测的交通供给和出行偏好等不能通过 RESET 或 BP 检验直接解决。

### 7.1 重点开展家庭聚类稳健标准误

虽然每名受访者现在只有一行记录，但来自同一个家庭的成员可能共享人口密度、车辆数及生活环境，因此不能自动假定其误差完全独立。

可使用：

```
library(lmtest)
library(sandwich)

# 普通回归结果
summary(m2)

# 异方差稳健标准误
coeftest(
  m2,
  vcov. = vcovHC(m2, type = "HC3")
)
```

然后再使用 `HOUSEID` 实现家庭聚类稳健推断。此时必须保证聚类标识和模型实际使用的观测行严格对应，不能在模型自动删除缺失值后直接传入长度不一致的 ID。

### 7.2 两种人口密度指标的比较

31 号文件采用：

- 主模型：`HTPPOPDN`，Tract 人口密度。
- 替代模型：`HBPPOPDN`，Block Group 人口密度。

这是一种很适合 Urban Analytics、同时不需要 GIS 工具的敏感性分析。

不过两种指标的八档类别未必具有相同的观测分布，因此应该在有共同有效数据的样本上进行可比分析，重点比较整体方向与预测结果，而不能机械地逐个比较同名类别系数。

### 7.3 权重问题

对于本研究的个人级结果，31 号文件强调应考虑 `WTPERFIN`，并区分：

1. 未加权样本中的条件关联。
2. 使用个人权重的总体相关估计。
3. 考虑抽样分层、家庭聚类及权重后的设计型方差估计。

如果只使用 `lm(weights = WTPERFIN)`，并不自动等同于已经正确实现完整复杂抽样设计。

更严格的可选方法是 R 的 `survey` 包，使用个人权重、`STRATUMID` 和家庭聚类信息来拟合模型。是否纳入正文，应以课程内容和实际篇幅为准。
